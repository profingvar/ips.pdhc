Authentication

All endpoints except /api/v1/health, /api/v1/metrics, and /fhir/metadata require authentication.

SSO Bearer Token

Authorization: Bearer <access_token>

The token is validated against the SSO service at OAUTH_BASE_URL/api/auth/me.

API Key

Authorization: Bearer <api_key>

API keys are SHA-256 hashed before lookup. The plaintext is shown once at creation.

When AUTH_DISABLED=true (development only), a synthetic dev user is attached. Never enable in production.

FHIR — Patient CRUD

POST /fhir/Patient

Create a new Patient resource.

Body: FHIR Patient resource JSON with resourceType: "Patient".

Response: 201 — created Patient resource with assigned id.

{
  "resourceType": "Patient",
  "name": [{"family": "Andersson", "given": ["Erik"]}],
  "gender": "male",
  "birthDate": "1985-06-15",
  "identifier": [{"system": "urn:oid:1.2.752.129.2.1.3.1", "value": "198506151234"}]
}

GET /fhir/Patient/{resource_id}

Read a Patient resource by FHIR resource ID.

Response: 200 — Patient resource JSON. 404 — OperationOutcome.

PUT /fhir/Patient/{resource_id}

Update a Patient resource (full replacement).

Body: Updated FHIR Patient resource JSON.

Response: 200 — updated Patient resource. 404 — OperationOutcome.

GET /fhir/Patient

FHIR — Clinical Resources

Supported resource types: Condition, Observation, MedicationStatement, AllergyIntolerance, Immunization, Procedure, DocumentReference, DiagnosticReport.

POST /fhir/{ResourceType}

Create a clinical resource. The resourceType field must match the URL segment.

Patient linkage is resolved from subject.reference or patient.reference (format: Patient/{id}).

Response: 201 — created resource.

{
  "resourceType": "Condition",
  "subject": {"reference": "Patient/abc-123-def"},
  "code": {
    "coding": [{"system": "http://snomed.info/sct", "code": "73211009", "display": "Diabetes mellitus"}]
  }
}

GET /fhir/{ResourceType}/{resource_id}

Read a clinical resource by type and ID.

GET /fhir/{ResourceType}?patient={patient_id}

Search clinical resources by patient. Returns a FHIR Bundle (searchset).

FHIR — $ips Operation

GET /fhir/Patient/{resource_id}/$ips

Generate an International Patient Summary (IPS) Bundle for the patient.

ParameterTypeDefaultDescription
modestringfullfull = all clinical types. minimal = Condition + MedicationStatement + AllergyIntolerance only.

Response: FHIR Bundle (type: "document") conforming to the IPS profile.

The bundle contains a Composition resource with LOINC-coded sections, the Patient, and all relevant clinical resources. Empty sections include an emptyReason code.

Application — IPS Cards

IPS cards represent a named summary concept tied to a patient. All GUIDs are UUIDs.

POST /api/v1/ips/cards

Create an IPS card.

FieldRequiredDescription
patient_guidYesPatient GUID (from PatientIndex)
clinic_guidNoAssociated clinic GUID
titleNoCard title (default: "International Patient Summary")
modeNofull or minimal (default: full)

Response: 201 — card object.

GET /api/v1/ips/cards

List cards. Optional filters: ?patient_guid=, ?clinic_guid=.

GET /api/v1/ips/cards/{guid}

Get a single card by GUID.

PATCH /api/v1/ips/cards/{guid}

Update card fields: status, mode, title.

DELETE /api/v1/ips/cards/{guid}

Archive a card (sets status to archived).

Application — IPS Snapshots

Snapshots capture an immutable point-in-time IPS bundle for a card.

POST /api/v1/ips/cards/{card_guid}/snapshots

Generate and store a snapshot. The bundle is generated using the card's mode.

Response: 201 — snapshot metadata (bundle not included).

GET /api/v1/ips/cards/{card_guid}/snapshots

List snapshots for a card (metadata only).

GET /api/v1/ips/snapshots/{guid}

Get snapshot metadata (bundle not included).

GET /api/v1/ips/snapshots/{guid}/bundle

Get the full IPS bundle JSON. Audited — an ips_bundle_read event is recorded.

Application — API Keys

Create a new API key. The plaintext key is returned exactly once.

FieldRequiredDescription

List API keys — shows prefix and metadata only, never the hash or plaintext.

Rotate: revokes old key and issues a new one. Returns the new plaintext once.

Error Handling

FHIR endpoints return errors as OperationOutcome resources:

{
  "resourceType": "OperationOutcome",
  "issue": [{
    "severity": "error",
    "code": "not-found",
    "diagnostics": "Patient/abc-123 not found"
  }]
}

Application API endpoints return errors as JSON objects:

{
  "error": "Patient not found"
}
HTTP StatusMeaning
200Success
201Created
400Bad request — missing or invalid fields
401Unauthorized — missing or invalid token/key
404Not found
